# polyforge-pipeline

Rust binary: market-data pipeline with two modes (selected in [src/main.rs](src/main.rs)).

- **Network mode** (arg ending in `.ini` or env `POLYFORGE_PIPELINE_CONFIG`): `parser` → `tcp_sender` → `tcp_receiver` → SPSC `ring_buffer` (2^20) → `processor` thread. The processor **owns** `ExchangeOrderBook` and returns it on `join()`; shutdown order matters (stop sender/receiver, drain ring buffer, then clear the processor's running flag).
- **File mode** (`<symbols file> <data files…>`): parses and applies messages directly.
- Config: [config.ini](config.ini) parsed by hand in [src/config.rs](src/config.rs) (keys lowercased, sections flatten to `section.key`, later duplicates win). Add new keys via `Config::from_ini` with a default.
- Input text formats are documented at the top of [src/parser.rs](src/parser.rs); samples in `test/`.
- Wire format: fixed 44-byte message (1 tag + 43 payload), 4-byte header, 34 msgs/packet. It is generated by the `define_precision_codec!` macro in [src/precision_codec.rs](src/precision_codec.rs) for `price4/6/9`. **Change layout in the macro only**, never per precision. [src/codec.rs](src/codec.rs) re-exports `price6`.
- Domain types come from `polyforge-core` (re-imported in `main.rs`), not defined here.
- Processor logs heavily with `println!`; keep hot-path changes allocation-light.
- Run: `cargo run -p polyforge-pipeline -- polyforge-pipeline/config.ini` (paths in config are relative to CWD).
- Default file-mode paths point to a sibling C++ repo (`../../C++/order-book/test/...`); pass explicit files instead.
